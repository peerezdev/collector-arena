# Collector Arena: console commands

Everything you can do from the terminal, grouped by what you want to achieve.

To **start the services**, see [STARTUP.md](STARTUP.md); it isn't repeated here.

Background on what these commands operate on: the battle wallets in
[ESCROW-WALLETS.md](ESCROW-WALLETS.md) and the gacha API in
[COLLECTOR-CRYPT-API.md](COLLECTOR-CRYPT-API.md).

---

## What to know first

**Backend scripts run from `backend/` and need `PYTHONPATH=.`**, otherwise they fail with
`ModuleNotFoundError: No module named 'app'`. There are two ways, depending on the script (each one
states which in its header):

```bash
cd backend
PYTHONPATH=. .venv/bin/python3 scripts/machines.py list     # most scripts
.venv/bin/python3 -m scripts.distribute_bot_usdc            # the bot scripts
```

**Devnet or mainnet.** Everything targets devnet by default. Prefixing `APP_NETWORK=mainnet` works
against mainnet instead: it switches the database (`battlearena.mainnet.db`), the RPC and the gacha
API.

```bash
APP_NETWORK=mainnet PYTHONPATH=. .venv/bin/python3 scripts/machines.py list
```

**Anything that moves money doesn't run unless you ask.** Every script that touches funds is a
*dry run* by default: it shows what it would do and does nothing. Note that **the flag isn't the same
everywhere**, a leftover from being written at different times:

| Flag | Scripts |
|---|---|
| `--go` | `sweep_stranded_cards`, `recover_escrow_usdc`, `escrow_pool_sync`, `rescue_and_buyback` |
| `--execute` | `distribute_bot_usdc`, `buyback_bot_nfts` |

**Local ports:** devnet frontend `5173` → backend `9090`; mainnet frontend `5273` → backend `9190`;
oracle `8787`.

## Day to day

From the repo root:

```bash
npm run dev            # frontend on :5173 (devnet)
BACKEND_PORT=9190 npm run dev -- --port 5273   # frontend against the mainnet backend
npm test               # frontend test suite (vitest)
npm run test:watch     # in watch mode
npx tsc -b             # the project's REAL type check
npm run lint           # eslint
npm run build          # tsc -b + vite build
```

> **`npx tsc --noEmit` checks nothing here.** The root `tsconfig.json` is only a references file
> (`{"files": [], "references": [...]}`). The real type check is **`npx tsc -b`**.

Backend:

```bash
cd backend
PYTHONPATH=. .venv/bin/python3 -m pytest -q          # full suite
PYTHONPATH=. .venv/bin/python3 -m pytest tests/test_settle.py -q
```

## Gacha catalog

Turn machines on and off **without restarting anything**: the backend reads the disabled ones on
every request and the frontend re-fetches the catalog every few seconds, so the change shows up on
its own.

```bash
cd backend
PYTHONPATH=. .venv/bin/python3 scripts/machines.py list
PYTHONPATH=. .venv/bin/python3 scripts/machines.py hide sweet_99 --reason "broken thumbnail"
PYTHONPATH=. .venv/bin/python3 scripts/machines.py show sweet_99
```

`list` marks each machine as `ok`, `cerrada` (closed by Collector Crypt) or `APAGADA` (disabled by
you). Disabling one removes it from the catalog **and** prevents new games from starting with it, in
both Pack Battle and Royale. It doesn't touch history: games already played keep their name and
image.

## Product switches

Turned on and off **without restarting**: the backend re-reads each flag every time it's used.

```bash
cd backend
PYTHONPATH=. .venv/bin/python3 scripts/flags.py list
PYTHONPATH=. .venv/bin/python3 scripts/flags.py on auto_royale pokemon_25      # 10 seats
PYTHONPATH=. .venv/bin/python3 scripts/flags.py on auto_royale pokemon_25:7    # 7 seats
PYTHONPATH=. .venv/bin/python3 scripts/flags.py off auto_royale
```

A **missing flag is off**: "not configured" and "disabled" are the same state.

| Flag | What it does |
|---|---|
| `auto_royale=<machine>` or `<machine>:<seats>` | Opens a house Battle Royale when none is waiting or in progress for that machine. The lobby has **no creator and charges nobody**: the first player to join takes the first seat. Without a seat count, 10; the mode supports 5 to 10. |

The loop checks every 30 s, so turning it on or off takes less than a minute to take effect. A house
lobby **can't be cancelled from the UI** (it has no creator); to remove one, turn the flag off and
cancel it in the database.

## Referrals

Codes are curated: they are only created through the CLI, there is no admin endpoint.

```bash
cd backend
PYTHONPATH=. .venv/bin/python3 scripts/referrals.py add ALICE \
    --name "Alice" --boost 0.10 --rake-share 0.25 --owner <WALLET>
PYTHONPATH=. .venv/bin/python3 scripts/referrals.py list
```

`--rake-share 0.25` is 25% of the rake generated by the code's referrals, in real USDC. `list` shows,
per code, how many referrals it has, how much is unclaimed and how much it has earned in total.

## Escrows and stuck money

These three are used together and **in this order** when something is left half done.

### 1. Cards that never reached their winner

```bash
cd backend
PYTHONPATH=. .venv/bin/python3 scripts/sweep_stranded_cards.py            # dry run
PYTHONPATH=. .venv/bin/python3 scripts/sweep_stranded_cards.py --go
PYTHONPATH=. .venv/bin/python3 scripts/sweep_stranded_cards.py --battle <id>   # a single battle
```

Walks the closed battles that have a winner, checks on-chain where each card is and delivers it. The
operator pays the gas. Idempotent: safe to run again.

### 2. USDC that never reached anyone

```bash
PYTHONPATH=. .venv/bin/python3 scripts/recover_escrow_usdc.py             # dry run
PYTHONPATH=. .venv/bin/python3 scripts/recover_escrow_usdc.py --go
```

To the winner if the game settled; each player's buy-in back if it was voided. **It doesn't pay out
when the balance doesn't match** the buy-ins of everyone who joined: that means someone was already
paid and it isn't recorded who, so it sets the funds aside instead of guessing.

### 3. Escrow wallet pool

```bash
PYTHONPATH=. .venv/bin/python3 scripts/escrow_pool_sync.py               # dry run / audit
PYTHONPATH=. .venv/bin/python3 scripts/escrow_pool_sync.py --go
```

Classifies every wallet as free, in use or retained (with the reason). Running it again is safe and
works as an audit: it re-evaluates retained wallets, so one that empties becomes free on its own.
**Run it after 1 and 2**, which is when wallets are actually empty.

## Test bots (devnet only)

```bash
cd backend
.venv/bin/python3 -m scripts.distribute_bot_usdc            # dry run
.venv/bin/python3 -m scripts.distribute_bot_usdc --execute  # tops USDC up to the target
.venv/bin/python3 -m scripts.buyback_bot_nfts               # dry run
.venv/bin/python3 -m scripts.buyback_bot_nfts --execute     # sells their cards to CC
```

The first tops up the 10 bots to a USDC target from the operator; if it can't confirm a bot's balance
**it skips it** instead of treating it as zero, so a flaky RPC can't cause an overpayment. The second
sells their cards back to Collector Crypt.

## One-off diagnostics

Single-use scripts born from specific investigations. They aren't part of any workflow; they are kept
because they document how something was verified.

| Script | Purpose |
|---|---|
| `verify_pack_pull.py` | One pack battle pull cycle on devnet (phase 1) |
| `verify_pack_battle.py` | Full single-player pack battle cycle on devnet (phase 2) |
| `verify_turbo_pull.py` | Check CC's auto-buyback in turbo mode |
| `verify_pnft_transfer.py` | Transfer a pNFT from escrow to winner |
| `verify_privy_sign.py` | That the backend signs and sends a Memo transaction |
| `cc_mainnet_pull.py` | A REAL gacha pull on mainnet (`--machine`, `--yes`) |
| `cc_core_transfer.py` | Move a CC Metaplex Core NFT between wallets on mainnet (`--to`, `--back`, `--yes`) |
| `rescue_and_buyback.py` | A one-off rescue with a hardcoded `BATTLE_ID` in the file. **Not a general sweep**; that's what `sweep_stranded_cards.py` is for |
